# Windows cursor parking for Apollo

Copy both PowerShell scripts to the Windows gaming PC, then run
`Install-Cursor-Park.ps1` as the Windows account used for gaming, from an
administrator PowerShell session. It installs a limited, interactive scheduled
task named `Moonlight Cursor Park`, started immediately and at that user's login.
No password is stored. Apollo configuration and services are not modified.

The helper reads Apollo's connection events from its default log location. While
a stream is connected, after the foreground window and mouse have been stable
for three seconds, it parks the pointer at that window's display's bottom-right
pixel. It does this once for the initial foreground window and once for each new
fullscreen foreground window in the connection. A new client connection resets
that list. Multiple connected clients are counted. This avoids continuously
fighting intentional mouse movement or a game's camera controls.

It sends no clicks or keys and never closes games. Games that repeatedly recenter
their pointer may still need game-specific cursor hiding. The foreground display
must be the display being streamed; this is not a per-client cursor because
Windows has one shared desktop pointer. A missing/restarted Apollo log is treated
as no stream until connection events appear. On log rotation the count is rebuilt
from the new log; a connection predating that log might need a reconnect.

Installed files and status: `%LOCALAPPDATA%\MoonlightCursorPark`. `status.json`
records the interactive session, target display and actual pointer coordinates.
Source backups are kept when reinstalling. To stop: `Stop-ScheduledTask -TaskName
'Moonlight Cursor Park'`. To uninstall: stop it, then `Unregister-ScheduledTask
-TaskName 'Moonlight Cursor Park' -Confirm:$false`.

Verified on 2026-10-23: task ran in desktop session 1; SetCursorPos succeeded on
DISPLAY16 with requested and actual coordinates both (1919, 1079). Apollo stayed
running. Reconnect and per-game visual behavior still merit user confirmation.

## Automatic streaming FPS limit

Install RTSS on the gaming PC:

```powershell
winget install --id Guru3D.RTSS --exact --source winget --silent --accept-package-agreements --accept-source-agreements
```

Copy `Stream-FPS.ps1`, `Get-Stream-FPS.ps1`, and `Install-Stream-FPS.ps1`
together, then run the installer in administrator PowerShell as the gaming user.
It creates interactive scheduled tasks `Moonlight RTSS` and `Moonlight FPS`,
started now and at login, plus an on-demand `Moonlight FPS Measure` diagnostic.
The helper uses RTSS's profile API (also used by Nonary/RTSSLimiter), but watches
Apollo's log so resumed streams can change the limit without a prep-command
restart. Apollo configuration is untouched.

With one active stream, the requested integer FPS becomes RTSS's global limit.
The original limit is saved locally before changing it and restored when there
are no streams. Reconnects update the limit. Multiple simultaneous streams or
fractional FPS are deliberately unsupported and restore the previous limit.
The helper assumes the default Apollo log location; a log reset with an existing
stream may require reconnecting. It does not alter VSync or per-game overrides.
Games with their own lower cap, RTSS exclusion, or incompatible hooking need
separate handling. Restart games that were running before RTSS was installed.

Files, status, and recovery state live in `%LOCALAPPDATA%\MoonlightFPS`:

- `status.json`: requested FPS, read-back global RTSS limit, and stream count.
- `previous-limit.json`: saved original limit while the override is active.
- `events.log`: changes and restores.
- `measured-fps.json`: actual RTSS application measurements, generated by running
  `Start-ScheduledTask -TaskName 'Moonlight FPS Measure'`. An absent game means
  RTSS has not hooked it; a matching global limit alone does not prove its FPS.

To disable and restore (administrator PowerShell):

```powershell
Stop-ScheduledTask -TaskName 'Moonlight FPS'
Disable-ScheduledTask -TaskName 'Moonlight FPS'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\MoonlightFPS\Stream-FPS.ps1" -Restore
```

Initial verification, 2026-10-23: detected the live 120-fps stream and read back
120 from RTSS. Installer rerun restored the original unlimited value (0), then
reapplied 120. After a real disconnect the log recorded restoration to 0; the next 60-fps
connection applied 60. After restarting Expedition 33, RTSS measured 59.06 FPS
in two fresh samples from SandFall-Win64-Shipping.exe, confirming the game is
running at approximately the requested 60 FPS. Game-level 120 FPS has not been
measured (the GPU may not reach that rate at the selected quality settings).

### Power and temperature check

A five-minute stationary Expedition 33 scene comparison on the RTX 3090 used
60 FPS for one minute, uncapped for two minutes, then 60 FPS for two minutes.
Averages from the final minute of the last two phases:

| Metric | Uncapped | 60 FPS cap |
|---|---:|---:|
| Measured game FPS | 64.49 | 60.07 |
| GPU power | 320.43 W | 320.02 W |
| GPU temperature | 73.95 C | 73.85 C |
| GPU utilization | 97.21% | 89.07% |
| Reported fan speed | 100% | 100% |

The cap worked, but power and temperature differences were within normal
fluctuation in this demanding scene. These are GPU readings from nvidia-smi,
not whole-PC wall power. This short test is not a thermal-equilibrium benchmark.
The automatic limiter was restored after the comparison.

## Password prompt after sleep

The gaming PC's active power plan was set to skip the password prompt after
sleep using the following administrator commands:

```powershell
powercfg /setacvalueindex SCHEME_CURRENT SUB_NONE CONSOLELOCK 0
powercfg /setdcvalueindex SCHEME_CURRENT SUB_NONE CONSOLELOCK 0
powercfg /setactive SCHEME_CURRENT
powercfg /qh SCHEME_CURRENT SUB_NONE CONSOLELOCK
```

Both values were verified as 0. Set them to 1 to restore the prior behavior.
This is an explicit host preference, not part of the FPS installer. It does
not configure automatic startup sign-in or unlock a manually locked session,
and no password is stored in this repository.
